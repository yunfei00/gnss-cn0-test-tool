# Windows x64 使用说明

## 安装和首次运行

运行 `GNSS-CN0-Setup-x64.exe` 安装到当前用户，或解压便携 ZIP 后打开其中的
`GNSS-CN0.exe`。通过发布旁的 `.sha256` 核对下载文件。正式签名尚未配置。

预先安装 Android Platform Tools，并将 `adb.exe` 加入 PATH。也可在上位机的
「连接设置」里指定 `adb.exe` 的完整路径。
两个 Android APP 均需支持协议 v1。用 USB 连接测试机，解锁并在手机上确认 USB 调试。
打开 Logger，按正常权限流程授予精确定位及后台定位，开启系统定位。
若已装 APK 的签名不同，可在两个 Android 源码仓库使用
`gradlew.bat assembleDebug -PgnssTestSideBySide` 构建并装包。安装后在 Windows
工具的「测试应用」默认自动识别。软件先检查正式版，如果不满足所选场景的协议要求，
再检查并装联调版。也可以明确指定其中一项。命令行选项为 `--test-apps`。

## 测试

1. 打开上位机后自动扫描设备，每 3 秒更新一次列表，也可以点击「重新扫描」立即更新。
   首次发现的设备只有一台且已授权时会自动选中。多台设备由操作员从列表选择，
   后续接入设备会加入列表，已选设备断开时需重新选择。列表使用脱敏标识。
2. 在「测试场景」网格中勾选需要执行的场景。网格提供亮屏、前置和后置默认摄像头预览、
   马达、音乐、视频、手电筒、录音机、白屏和灭屏。默认勾选亮屏、视频和灭屏，
   稳定等待 20 秒、测量 60 秒、重复 1 次。三个设置对本轮所有勾选的场景生效。
   勾选「自动测试」时可多选，按网格顺序执行。取消勾选后只保留一项，优先保留已选的灭屏，
   或保留网格中的第一项。点击另一场景可直接切换手动采样目标。
   自动场景能力由手机查询，新增应用场景需要新版 AutoTestSceneApp。
   摄像头以 Android 选择的前后默认预览为准，具体物理镜头由机型决定。
   录音机需要先授予麦克风权限，自动测试生成的临时录音不导出。包含自动灭屏的计划会在
   启动 Logger 前唤醒手机并尝试解除锁屏，完成灭屏窗口后也会恢复亮屏并检查锁屏。
   如果 Android 要求密码或指纹，请在手机上完成验证后重试。
   勾选灭屏后，Logger 在屏幕实际关闭期间持续采集，报告使用第一个有效灭屏窗口作参照，
   即使它排在最后。若手机进入息屏显示（DOZE）或灭屏窗口无效，报告保留各场景数据并提示
   基准缺失。若使用息屏显示，请关闭该功能后重测完全灭屏。
   单独手动测灭屏时，请先点「开始手动采样」，等日志提示后按手机电源键。检测到主屏全灭
   才会计入稳定等待和采样。测完会自动唤醒，便于查看结果。
3. 测试手机上的第三方应用时，保留一个场景并取消勾选「自动测试」，也可以点击「添加手动场景」。
   先在手机上打开目标页面，
   再点「开始手动采样」。如果手机限制 Logger 从后台启动，请先点「准备采集」，
   看到「采集已准备好」后自行切到目标页面，再点「开始手动采样」。采样启动后电脑保持
   手机页面，独立完成稳定等待、采样和报告。若 Logger 已在采集，先结束现有采集。
4. 底部进度区显示当前场景、已处理次数和稳定或采样阶段的剩余时间。「运行日志」保留本轮带时间的
   场景切换、阶段进度和失败原因。可在完整场景结束后暂停，
   或取消整个任务。在「历史与报告」查看频段结果和趋势。报告保存在 `%LOCALAPPDATA%\GNSS CN0\runs`。
   「打开每秒数据」可打开 `observations_1s.csv`，同名 Excel 表也包含测量窗口内每秒一行的记录。
   `time_beijing` 是该秒起点，`frame_time_beijing` 是该秒第一帧的真实采集时间；
   `recorded_frames` 表示该秒实采帧数。无回调的行标为 `NO_FRAME`，不补数。
   `satellite_observations` 逐条列出实际卫星观测，保留北京时间、原 UTC 毫秒与单调纳秒。
   手机按 GNSS 回调保存原始数据，约一秒一次与每秒表的固定网格可能存在偏差。

载入旧计划时，若各场景的时长或重复次数不同，界面使用首个场景的值并写入运行日志。
旧计划包含同名场景时，合并重复场景后再载入；已有计划文件保留原样。

卫星状态和事件默认存档。计划 JSON 可以通过 `collect_raw: true` 启用
Raw Measurements，通过 `collect_nmea: true` 启用 NMEA。
Raw 和 NMEA 联采在当前测试手机上出现超时，正式测量使用默认采集选项。
位置列在自动化采集中的卫星 CSV 留空。Raw 和 NMEA 可能包含敏感信息，
运行目录仅供本机分析。日志在传回之后按大小、SHA-256 和行数核验。
没有可比卫星或 L5 数据时报告显示对应原因，差值单元格留空。

## 开发、回放和回收

```powershell
uv sync --locked --extra dev --python 3.12
uv run gnss-cn0 gui
uv run gnss-cn0 replay C:\path\to\run
uv run gnss-cn0 recover C:\path\to\run --serial YOUR_ADB_SERIAL
uv run gnss-cn0 run examples/auto-smoke.json --serial YOUR_ADB_SERIAL
```

断线后用原设备回收同一个 run。未收到结束标记的窗口标记为无效。
丢失会话或 Android 开机纪元改变时，应另开任务。
离线回放读取 `raw/manifest.json` 及其中列出的文件，重新生成 `reports/`。

## 构建

```powershell
uv sync --locked --extra dev --python 3.12
.\packaging\build.ps1 -Python .\.venv\Scripts\python.exe -Iscc 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe'
```

在干净的 Windows 10/11 x64 环境验收时，准备 Platform Tools 和两款 APP，
先分别安装和运行安装版及便携版并执行一次离线回放，再用实际手机跑默认计划。
